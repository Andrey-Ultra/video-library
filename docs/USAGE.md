# Руководство Video library

Локальный индекс видеоархива для вопросов и работы LLM-агента через MCP.

`main.py` рекурсивно находит видео в папке, извлекает речь на исходном языке и английский текст
на экране, описывает изображение, строит события и сводки, сохраняет поисковые
эмбеддинги. После этого можно задавать вопросы из терминала или подключить MCP.
Исходные видео не изменяются. Физическая нарезка не требуется.

## Локальное приложение

На Mac откройте **Video library.app** в корне проекта двойным щелчком.
Команда ниже собирает приложение при необходимости и открывает его:

```bash
.venv/bin/python main.py ui
```

Это нативный интерфейс SwiftUI/AppKit на английском с системными окнами,
диалогом выбора папки и AVKit-плеером. Браузер и WebView не используются.
Визуальный стиль тёмный с мягкими бирюзовыми акцентами и градиентным логотипом Vl.
Розовый используется только в градиенте логотипа.

Нужны macOS 14+ и Command Line Tools (`xcode-select --install`) для первой сборки.
Сборка без Xcode-проекта: `.venv/bin/python scripts/build_desktop.py`.
`main.py ui --rebuild` выполняет полную пересборку; **Video library.command**
тоже открывает нативное приложение. Бандл `.app` исключён из Git и создаётся
из `desktop/Sources/*.swift`; иконка рисуется AppKit в `desktop/Icon.swift`.
Текущая сборка использует Python-окружение и модели рядом с исходниками проекта:
для переноса репозитория приложение нужно пересобрать. Это ещё не автономный
дистрибутив с упакованными Python и моделями. Нативный клиент пока для macOS;
CLI, модули индексации и MCP сохраняют поддержку других платформ.
При первом запуске macOS может попросить доступ к «Документам»: в этой папке
на текущем Mac лежат проект, Python-окружение и видео. Запрос нужно разрешить
в системном диалоге. После пересборки локально подписанного приложения macOS
может запросить разрешение повторно, поскольку изменяется подпись бинарника.
Пока запрос ожидает решения, приложение показывает экран загрузки.

- **Add folder** — выбрать папку через системный диалог macOS.
  Для новой папки сразу открывается мастер индексации: выберите слои/модели и нажмите
  **Start indexing**. До подтверждения папка не добавляется в список и её индекс не создаётся.
  Если сохранённый конфиг уже есть в папке, мастер не показывается: настройки и checkpoints
  загружаются из индекса, незавершённая работа продолжается без пересчёта готовых слоёв.
  Полностью готовая папка просто открывается; для проверки новых файлов используйте Refresh folder.
- **Hide to Menu Bar** в меню приложения (⇧⌘M) — спрятать окна и значок Dock, оставив Vl в строке
  меню macOS. Закрытие последнего окна тоже оставляет приложение в фоне.
  Через Vl → **Show Video library** можно вернуть окно; повторное открытие .app
  в Finder тоже возвращает приложение. Открытые окна при скрытии сохраняются,
  видеопредпросмотр ставится на паузу, индексация продолжает работу.
  Меню Vl показывает выполняющуюся задачу, её папку, этап, прогресс и число
  ожидающих задач независимо от выбранной библиотеки. **Show queue** открывает
  очередь в приложении. **Quit Video library** или ⌘Q закрывает интерфейс и
  внутренний API; отдельный процесс продолжает выполнять добавленную очередь.
- **Add to queue** — добавить индексацию выбранной папки. Уже добавленная папка
  повторно не ставится в очередь. Для готовой папки **Refresh folder** добавляет
  синхронизацию и обработку недостающего. При добавлении новой библиотеки сначала
  ставится лёгкая задача сканирования.
- **Queue** внизу раскрывает общую очередь: текущую задачу и ожидающие; прошлые задачи не отображаются. Ожидающие можно переставить стрелками или убрать; исходники
  и индекс при этом не удаляются. Приостановленные задачи тоже можно переставлять;
  выполняющуюся — после сохранения её контрольной точки. Повтор ошибочной обработки
  запускается из соответствующей библиотеки через **Add to queue**.
- **Pause queue / Resume queue** сохраняют контрольную точку текущей задачи и
  управляют всей очередью. После сбоя очередь ждёт Resume; после обычного закрытия
  интерфейса продолжает работу. Ошибка одной задачи не мешает следующей.
  Методы и модели фиксируются при добавлении задачи; последующая правка настроек
  папки относится к новым задачам. На машине работает один процесс индексации.
- Нижняя панель всегда показывает выполняющуюся задачу, её папку, слой и файл, долю покрытия слоёв и число
  полностью готовых роликов. Процент покрытия не является долей прошедшего времени.
  ETA использует типичные завершённые замеры с теми же настройками и недавнюю
  скорость сохранения контрольных точек. Первый медленный кадр не заменяет
  накопленную статистику. Пока будущие слои ещё не измерены, показывается время
  оставшейся работы текущего слоя с его названием; когда измерены все слои —
  общее оставшееся время. При недостатке данных или нестабильной скорости
  отображается **ETA · measuring current stage / recalibrating**.
- **Refresh folder** — найти новые/изменённые файлы, синхронизировать удаления
  и переименования, затем проиндексировать недостающее выбранными методами.
- **Index coverage** показывает выбранное разрешение, предел FPS, частоту выборки,
  модели и сохранённое покрытие каждого слоя. Кнопка **Indexing settings…** внизу
  открывает настройки выбранной папки; во время её обработки сначала нужна пауза.
- **ПКМ по папке → Indexing settings…** — выбрать обработку на этом Mac или сервер
  с OpenAI-совместимым API для визуального понимания. Локальные модели выбираются
  из списка; кнопка **Download** скачивает модель в общий кэш для всех папок.
  Видны состояния загрузки, проверки, готовности и ошибки с **Retry download**.
  До старта выбранные встроенные модели должны быть скачаны. Apple Vision для OCR
  встроен в macOS и загрузки не требует. Parakeet v3 автоматически распознаёт русский
  и другие поддерживаемые языки; v2 предназначен только для английского.
  **Suggest for this Mac** проверяет чип и объём памяти и предлагает начальные параметры:
  2B / 4 кадра для 8 ГБ, 2B / 6 кадров для 16–24 ГБ, 4B / 8 кадров для 32 ГБ и выше.
  Это начальная рекомендация по памяти, не замер скорости. Разрешение/FPS прокси,
  каталог кэша и модель ответов при этом сохраняются. Изменения применяются только после сохранения.
  Перекрытие окон и размер изображений находятся в **Advanced sampling** с пояснениями;
  JSON для собственных моделей/существующих backend остаётся в **Advanced configuration**.
  **Apply & index** сразу сбрасывает только изменённые слои и ставит недостающую обработку
  в очередь. При смене речи визуальные данные, OCR, дерево и их векторы остаются;
  поиск достраивается для новых транскриптов. При сохранении одинаковых настроек
  checkpoints не сбрасываются. Профили NVIDIA убраны из интерфейса Mac;
  экспериментальные настройки CLI описаны отдельно ниже.
- Один щелчок по ролику показывает компактную сводку и статусы справа.
  Двойной щелчок или **Explore this clip** открывает отдельное подробное окно.
  Фильтр основной таблицы ищет по имени файла.
- В подробном окне есть **Overview**, **Video tree**, **Visual windows**,
  **Speech**, **On-screen text**, **Index details**. Дерево раскрывается до
  исходных окон; речь, OCR и визуальные окна имеют поиск и постраничную загрузку
  внутри одного выбранного ролика. Нажатие на наблюдение перемещает плеер к его
  таймкоду и показывает полный текст, исходный payload, неопределённости, связанные
  речь/OCR, родителей и настройки модели. Для OCR сохраняются confidence и box,
  время показывается с миллисекундами как отдельный sampled frame.
  Окно привязано к library ID и video ID: переключение активной папки его не меняет.
- У плеера собственные Play/Pause, громкость и шкала всего исходника. Розовая
  полоса обозначает выбранный интервал; OCR отмечается отдельным маркером кадра.
  Выделение не обрезает видео и не останавливает воспроизведение на своей границе.
  **Play selection** каждый раз возвращает к началу выбранного наблюдения,
  дожидается завершения перемотки и запускает воспроизведение. Обычная кнопка
  плеера продолжает с текущей позиции. На шкале можно щёлкать и перетаскивать
  ползунок в любую часть ролика; при фокусе на шкале ←/→ перемещают на 5 секунд,
  пробел переключает Play/Pause.
- **Pause / Resume indexing** — безопасно остановить обработку после текущей
  единицы работы и продолжить по checkpoints. Индексация работает в отдельном
  процессе: закрытие приложения её не останавливает. После аварии
  самого worker приложение предлагает Resume. Незавершённая единица работы
  выполняется повторно; готовые окна, блоки речи, OCR, векторы и проверенные
  промежуточные части дерева сохраняются.
- Прогресс и ETA приблизительные. Оценка использует скорость совместимых
  моделей в текущей и других библиотеках; без замеров показывается калибровка.
  Загрузка моделей, перезапуск Apple Vision и разные кодеки могут менять ETA.
- **Connect your agent** — копировать stdio JSON, Codex TOML или готовую команду
  `codex mcp add`. Эта конфигурация следует активной папке без переподключения.
  Форматы Codex сверены с [официальной документацией MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

Состояние приложения и журналы задач — `.cache/app/app.sqlite3` и `.cache/app/*.log`.
Индексы остаются внутри соответствующих папок с видео. Путь состояния можно
изменить через `--state-dir` или `VIDEO_AGENT_STATE_DIR`; тот же путь должен
быть указан в MCP-конфигурации. Приложение запускает внутренний Python API на
случайном свободном порту `127.0.0.1`; он не обслуживает HTML или frontend-файлы.
API записи проверяет Host, Origin и заголовок локального приложения; CORS не включён.
При явном Quit приложение завершает внутренний сервис; скрытие и закрытие окон
его не останавливают. Проверка parent PID также завершает
его после аварии нативного процесса. Отдельный worker индексации продолжает работу.

## Быстрый старт: Mac с Apple Silicon, 16 ГБ

Нужны Python **3.12–3.14** и FFmpeg. Проверенный вариант — Python 3.12.

```bash
brew install ffmpeg
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e '.[mac]'
python main.py doctor --profile fast
python main.py /path/to/videos --profile fast --chat
```

Без аргументов `python main.py` индексирует папку `videos` в текущем каталоге.
Можно просто положить туда исходники. Скрытые файлы, AppleDouble `._*`, скрытые
каталоги и символические ссылки не обрабатываются.

По умолчанию используется Qwen3-VL **2B 4-bit** (профили `mac` и `fast`).
Для более подробных описаний есть `--profile quality` с моделью **4B 4-bit**.
Для формулирования ответов используется отдельная текстовая
`Qwen3-4B-Instruct-2507` через MLX-LM; её настройки находятся
в секции `[answer]`. Она загружается после выгрузки модели эмбеддингов.
Сначала рекомендуем проверить обработку на небольшой папке:

```bash
python main.py /path/to/videos --profile fast --max-videos 1
python main.py overview /path/to/videos
python main.py search /path/to/videos 'a person hiding under a table'
python main.py search /path/to/videos 'Access denied' --source ocr --lexical-only
python main.py ask /path/to/videos 'Что происходит в этих видео?'
python main.py ask /path/to/videos 'Что видно в этом файле?' --video-id 1
```

Вопросы могут быть на русском. Описания и OCR пока ориентированы на английский;
речь сохраняется на исходном языке. Для точного поиска по речи используйте язык транскрипции. В чате каждый вопрос независимый:
контекст диалога не сохраняется. `/exit` завершает чат.
Если в вопросе указано уникальное полное имя файла, контекст автоматически
ограничивается этим видео. Для однозначного выбора используйте `--video-id`.

При первом запуске модели скачиваются с Hugging Face. Основная обработка локальная.
Кэш по умолчанию — `.cache/models` в проекте. В sandbox/headless-сеансах MLX и
Apple Vision могут не иметь доступа к GPU/системным сервисам: запускайте из обычного
терминала macOS. После загрузки можно установить `HF_HUB_OFFLINE=1` для офлайн-работы.

Предварительная загрузка выбранных моделей:

```bash
python scripts/download_models.py --profile fast
```

## Что находится в индексе

- **Визуальные наблюдения:** окна по 10 секунд, шаг 8 секунд; по умолчанию 6 кадров
  на окно, уменьшенных до 448 px по длинной стороне. Модель описывает видимое,
  объекты, действия, окружение и неопределённость. Реальные таймкоды кадров сохранены.
- **Речь:** Parakeet TDT 0.6B v3 через MLX; автоматическое распознавание 25 европейских
  языков, включая русский, английский и украинский, за один проход с временными
  метками слов/фраз. В меню папки Indexing settings… → Speech transcription модель выбирается из списка;
  v2 остаётся для английской речи. Сохранённые библиотеки не переключаются автоматически:
  выберите v3 и добавьте папку в очередь, чтобы пересчитать речь и зависимый поиск.
  Для Faster Whisper доступны Auto (язык переопределяется между окнами декодирования)
  и конкретный язык. Auto не ограничивается списком популярных языков в интерфейсе.
  Текст не переводится. Смешанная речь может распознаваться с ошибками; v3 не возвращает
  метки языка отдельных фраз, поэтому они остаются неизвестными, а не помечаются как English.
  [Поддерживаемые языки Parakeet v3](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3).
  Аудио обрабатывается блоками по 120 секунд с контекстом у границ.
  Интервалы ASR приблизительны; на границах блоков возможны повторы или пропуски.
- **OCR:** Apple Vision, английский, 1 кадр/с. Хранятся текст, уверенность и координаты.
  Время OCR означает **наблюдение на конкретном кадре**, а не доказанный непрерывный
  интервал присутствия надписи. Пустые наблюдения тоже продвигают checkpoint.
  Apple Vision работает в отдельном процессе, который обновляется после 400 кадров,
  чтобы не накапливать нативное состояние. При сбое кадр повторяется на CPU;
  если процесс остаётся неисправным, он перезапускается и повторяет тот же кадр.
  Постоянная ошибка остаётся явной: кадры без обработки не пропускаются.
- **События и иерархия:** модель объединяет соседние визуальные окна в события;
  затем создаются более крупные эпизоды и сводка видео. Каждый узел ссылается на
  дочерние наблюдения. Группировка событий выполняется ограниченными пакетами,
  поэтому одно долгое событие может оказаться в нескольких узлах. Верхние уровни
  группируются хронологически; это не гарантированное смысловое деление на главы.
- **Метаданные:** путь, длительность, разрешение, FPS, наличие аудио, доступные теги.
- **Поиск:** Qwen3-Embedding 0.6B по описаниям, событиям, речи и OCR; SQLite FTS5
  для слов. Списки объединяются reciprocal rank fusion. Прямых визуальных эмбеддингов
  и поиска по эталонному изображению в этой версии нет.

Визуальные сводки строятся **только по изображению**. Произнесённое и написанное
на экране хранится отдельно: слова о лисе не означают, что лиса видна в кадре.
Агент может получить пересекающиеся по времени речь/OCR при раскрытии узла.

Редкие объектные метки помогают исследовать архив без готового поискового запроса.
Это частоты **окон**, а не посещений, животных или уникальных событий. Названия
объектов генерируются моделью и пока не нормализуются в единую онтологию.

## Возобновление и смена модулей

Повторите ту же команду после остановки или ошибки. Завершённые этапы пропускаются;
визуальные окна, аудиоблоки, OCR и векторы имеют checkpoints. Незавершённые этапы
не участвуют в поиске. Дерево публикуется целиком, после проверки ссылок на все окна.

```bash
cp video-library.example.toml video-library.toml
python main.py /path/to/videos --config video-library.toml
```

Каждый слой имеет отдельные `backend` и `model`. Настройки и версия промптов
сохраняются с этапом. Изменение модели речи пересчитывает речь и эмбеддинги,
но не визуальные окна и не визуальную иерархию. OCR также не меняет визуальное дерево.
Изменение модели эмбеддингов пересчитывает
только векторы. Разные пространства эмбеддингов не смешиваются.

`backend = "none"` отключает выбранный слой. Для отключения визуального слоя
нужно также `hierarchy.enabled = false`. Тогда поиск по речи/OCR продолжит работать.
Модель ответов задаётся независимо в `[answer]`; `answer.backend = "none"` отключает
только терминальные генеративные ответы, оставляя поиск и MCP.

`--force` пересчитывает все выбранные этапы. Используйте его также, если веса
удалённой модели обновились под тем же названием: ревизии весов автоматически
не отслеживаются. Идентификация изменения файла использует размер, mtime и хеш
выборки данных, а не полный побайтовый хеш всего видео.

Индекс: `<папка видео>/.video-library/library-v2.sqlite3`.
При открытии старого индекса для записи папка `.video-agent` переносится в `.video-library`
целиком, без переиндексации. Перед переносом закройте старую версию приложения и активные
MCP-запросы: открытая база не перемещается. Чтение старого пути поддерживается до переноса.
Если обе папки содержат данные, автоматическое объединение не выполняется.
Файлы `._.video-library` на внешнем диске — служебные метаданные macOS (AppleDouble), не индекс.
 Старые `index.db`
и Chroma не перезаписываются и автоматически не мигрируются. База v2 обновляется
аддитивно, готовые наблюдения остаются на месте.

Синхронизация использует быстрый хеш размера и первого/среднего/последнего мегабайта,
отдельно от mtime. Обычное переименование внутри файловой системы определяется
по content hash и device/inode, ID и готовый индекс сохраняются. Для кандидатов
в дубликаты дополнительно сравнивается полный SHA-256 содержимого. Копии хранятся
как разные пути одного видео и не обрабатываются повторно. Если основная копия
исчезла, выбирается оставшаяся. После удаления последней копии удаляются её
наблюдения, дерево, FTS и векторы — исходные видео приложение никогда не удаляет.
Ошибка чтения папки отменяет синхронизацию, а не превращает её в пустую библиотеку.

Быстрый хеш не гарантирует обнаружение изменений вне sampled-областей, если размер
и файловая идентичность сохранены. При переносе через copy/delete без доступной
старой копии, смене inode и отсутствии ранее сохранённого полного хеша приложение
консервативно создаст новый индекс. До первого обновления старой базы должны быть
доступны её исходные пути, чтобы сохранить идентичность для будущих переименований.
Параллельная запись двумя индексаторами запрещена файловым lock.

## MCP

```bash
python mcp_server.py /path/to/videos
# или
python main.py serve /path/to/videos
# следовать активной папке приложения, в том числе при закрытом UI
python mcp_server.py --active --state-dir /absolute/path/video-library/.cache/app
```

MCP использует настройки, сохранённые в индексе. Индексация выполняется отдельно.
Пример конфигурации клиента (подставьте абсолютные пути):

```json
{
  "mcpServers": {
    "video-library": {
      "command": "/absolute/path/video-library/.venv/bin/python",
      "args": ["/absolute/path/video-library/mcp_server.py", "/absolute/path/to/videos"]
    }
  }
}
```

Инструменты:

- `library_context()` — текущая папка и режим следования активной библиотеке.
  После переключения папки агенту нужно обновить обзор: ID локальны для библиотеки.
- `library_overview(offset, limit)` — файлы, визуальные сводки и статус этапов.
- `search_library(query, top_k, video_id, source, lexical_only)` — слова и смысл;
  источники: `all`, `visual`, `speech`, `ocr`, `hierarchy`.
- `list_events(video_id, kind, offset, limit)` — хронологический обзор без запроса;
  виды: `event`, `episode`, `window`, `speech`, `ocr`, `summary`.
- `inspect_item(item_id)` — полное наблюдение, неопределённость, родители, дети,
  происхождение и пересекающиеся речь/OCR.
- `list_children(item_id, offset, limit)` — раскрытие дерева.
- `object_inventory(video_id, limit)` — объектные метки с частотами и примерами.
- `get_frame(video_id, time_s)` — проверка настоящего кадра исходника.

В режиме `--active` MCP-поиск разделяет блокировку памяти с worker приложения.
Во время индексации он возвращает поиск по словам с явным предупреждением;
семантический поиск снова доступен после завершения. Обзор, дерево и исходные
кадры можно читать во время обработки опубликованных слоёв.

Все временные параметры MCP — **секунды**. Внутри базы — миллисекунды,
интервалы полуоткрытые `[start, end)`. Score — ранг, не вероятность правильности.
Для исследования большого архива агент должен пользоваться пагинацией и деревом.
Терминальная команда `ask` — упрощённый RAG: до 10 сводок, 12 поисковых результатов
и примеры редких меток. Для речи, OCR и визуальных наблюдений выделены отдельные
места в контексте, чтобы повторяющиеся субтитры не вытесняли другие источники.
Команда не перечитывает весь архив при каждом вопросе.

## NVIDIA / другие модели

```bash
pip install -e '.[cuda]'
python main.py /path/to/videos --profile cuda --config video-library.toml
```

В CUDA-профиле визуальная модель вызывается через **OpenAI-compatible endpoint**,
по умолчанию `http://localhost:8000/v1`. Сервер vLLM/совместимый сервер запускается
отдельно. По умолчанию выбрана Qwen3-VL 8B; речи соответствует faster-whisper,
OCR — EasyOCR, эмбеддингам — Sentence Transformers. Поддержка конкретного GPU
зависит от сборок CUDA/PyTorch и сервера. Этот профиль реализован, но на NVIDIA
в данной среде не проверялся. Значения в TOML имеют приоритет над профилем.

При `visual.backend = "openai"` выбранному вами endpoint передаются кадры/тексты.
При `answer.backend = "openai"` endpoint получает вопрос и извлечённый контекст.
API-ключ берётся из переменной `VIDEO_AGENT_API_KEY`, если она задана; секреты
в индекс не сохраняются. Без явного выбора этого backend облачные API не используются.

## Скорость и ограничения

Цель — около минуты обработки на минуту исходника, но гарантии пока нет.
На M4 / 16 ГБ быстрый профиль обработал 65,76 с тестового материала за 52,49 с;
4B — минутный фрагмент за 75,12 с. Подробности и границы замера — в [BENCHMARKS.md](../BENCHMARKS.md).
В итоговом отчёте есть wall time, длительность видео и `processing_ratio`:
меньше 1 — быстрее реального времени. При повторном запуске эта метрика отражает
только выполненную в этом запуске работу, поэтому для сравнения нужен полный прогон
на новой папке или `--force`, с уже скачанными моделями.

Тяжёлые модели загружаются по очереди, чтобы снизить пик памяти. SQLite хранит и
структуру, и float32-векторы. Поиск векторов пока точный, блоками по 256 записей:
он экономит память, но линейно зависит от размера индекса. Сервер/Chroma для первой
версии не нужен; при росте архива векторное хранилище можно заменить.

Редкая выборка кадров может пропустить короткое событие. Модели могут ошибаться
в действиях, видах животных и описаниях. Ни сводка, ни отсутствие результата не
доказывают отсутствие события в 20-часовом видео. Важные находки нужно проверять
по исходным кадрам. Сборка/рендер монтажа, анализ музыки и звуков, идентификация
говорящих и полноценная оценка качества кадров пока не входят в эту версию.

## Прокси для анализа

В меню папки Indexing settings… → Analysis proxy можно выбрать Original, Up to 1080p или Up to 720p,
а также предел частоты кадров Original / 30 / 15 / 5 fps. По умолчанию оба параметра
сохраняют исходник. Небольшие видео не увеличиваются, низкий FPS не повышается.
Портретные видео сохраняют ориентацию и пропорции.

Временные H.264-копии используются только для OCR и визуальных наблюдений.
Проигрыватель, извлечение речи и MCP get_frame работают с оригиналом.
FPS прокси не меняет скорость видео и не равен частоте выборки кадров для ИИ.
При снижении FPS соответствие исходному кадру приблизительное в пределах интервала кадра прокси.
Модель уже получает кадры до 448 px, OCR — до 1280 px по длинной стороне:
прокси помогает сократить повторное декодирование тяжёлого исходника, а не число вызовов ИИ.
Создание копии требует времени и места, поэтому ускорение общего процесса не гарантировано.
720p может ухудшить распознавание мелких надписей, а низкий FPS — пропустить короткие события.

Настройки сохраняются на папку и включаются в задачу при постановке в очередь.
Изменение прокси пересчитывает визуальные наблюдения, OCR и зависимые слои;
сохранённая речь используется повторно. Временный кэш ограничен 512 МиБ на запуск,
с резервом свободного места 256 МиБ; старые копии вытесняются по мере необходимости.
Длинные ролики обрабатываются временными частями до 60 секунд. Если часть превышает
лимит кэша, её длительность автоматически сокращается, а выбранное разрешение и FPS
сохраняются. Таймкоды относятся к исходному видео, продолжение начинается около
сохранённой контрольной точки. Лимит также можно изменить через `proxy.cache_mb`
в полном JSON или TOML-конфигурации; это не пересчитывает индекс.
После завершения, ошибки или паузы временные копии удаляются. При продолжении задачи
прокси могут создаваться заново; checkpoints индекса сохраняются.

## Удаление библиотеки и индекса

Чтобы начать индексацию заново, нажмите ПКМ по папке → **Delete index…**.
После подтверждения индекс и задачи этой папки удаляются, сама папка остаётся
в Libraries и сразу открывается настройка индексации с предыдущими параметрами.
Новая обработка начинается только после **Start indexing**; Cancel оставляет папку
без индекса. Исходные видео сохраняются.

Чтобы также убрать папку из списка, выберите **Delete library and index…**.
После подтверждения папка исчезает из списка, её индекс и оставшиеся задачи удаляются.
Исходные видео остаются на месте. Повторное добавление потребует новой индексации.

Для обрабатываемой папки сначала приостановите задачу и дождитесь сохранения checkpoints.
Индекс с открытыми подключениями или посторонними файлами не удаляется.
Последняя удалённая папка не добавляется автоматически при перезапуске приложения.
После удаления последней задачи очередь возвращается в обычное пустое состояние;
новые задачи не наследуют её прежнюю паузу. При наличии оставшихся задач пауза сохраняется.

Для первой загрузки Parakeet v3 требуется около 3 ГБ свободного места в кэше моделей.
При нехватке места задача завершается с явной ошибкой без повторных попыток для каждого
ролика. Освободите место и добавьте библиотеку в очередь снова; checkpoints сохраняются.
Если очередь была вручную приостановлена, сначала нажмите Resume queue.

## Настройки и продолжение обработки в папке

В `.video-library` хранятся:

- `config.json` — читаемая копия выбранных настроек индексации;
- `library-v2.sqlite3` — сами данные, конфигурация, состояния слоёв каждого файла,
  сигнатуры методов, частичные checkpoints и параметры, с которыми были получены результаты.

SQLite — основной источник состояния. JSON записывается атомарной заменой файла при сохранении
настроек; состояния изменяемых слоёв обновляются в одной транзакции SQLite.
Если папка была проиндексирована раньше и не зарегистрирована в текущем приложении,
**Add folder** восстанавливает её настройки и продолжает обработку. Полностью готовые
и совместимые слои используются повторно. Старые индексы с конфигом только в SQLite тоже читаются.

Настройки открываются в мастере при добавлении новой папки и через её контекстное меню;
глобальной кнопки настроек моделей вверху нет. Справа показано сохранённое покрытие слоёв.
Окно настроек закреплено за своей папкой и не зависит от текущего выбора в основном окне.
Для изменения обрабатываемой папки сначала поставьте её задачу на паузу и дождитесь checkpoints.
Изменение настроек отменяет ожидающие задачи этой папки со старым снимком конфигурации;
после применения создаётся задача с новым снимком. Если общая очередь на паузе, нажмите Resume queue.


### Загрузка моделей в настройках

Программа не поставляется с предустановленными весами. Список локальных моделей
проверяется без сети и без загрузки весов в память. Новое скачивание запускается
только кнопкой Download; отдельный процесс продолжает загрузку при закрытии окна.
При повторе после обрыва используются файлы кэша Hugging Face. После скачивания
проверяются конфигурация, структура/размер весов и контрольные суммы крупных файлов.
Повреждённый результат требует повторного скачивания и не помечается Ready.
Если загрузчик был прерван, при следующем открытии показывается ошибка с повтором.
Временный обрыв сети и нехватка диска не меняют конфиг папки и готовые checkpoints.
Собственные модели/пути из Advanced configuration устанавливаются самостоятельно.
Ошибка загрузки локальной модели при индексации останавливает задачу с сообщением,
а не повторяется для каждого ролика.

Каталог: [Qwen3 VL 2B](https://huggingface.co/mlx-community/Qwen3-VL-2B-Instruct-4bit),
[Qwen3 VL 4B](https://huggingface.co/mlx-community/Qwen3-VL-4B-Instruct-4bit),
[Parakeet v3](https://huggingface.co/mlx-community/parakeet-tdt-0.6b-v3),
[Parakeet v2](https://huggingface.co/mlx-community/parakeet-tdt-0.6b-v2),
[Qwen3 Embedding](https://huggingface.co/mlx-community/Qwen3-Embedding-0.6B-4bit-DWQ).


### Очистка кэша и сторонние модели

Рядом со статусом скачанной модели есть корзина. После подтверждения удаляется
только репозиторий этой модели из общего кэша (все его версии и недокачанные файлы).
Индексы папок и исходные видео сохраняются; после удаления появляется Download.
Apple Vision встроен в macOS, кнопки удаления у него нет. Занятые модели,
активные загрузки и модели, нужные текущей очереди, удалить нельзя.

В выборе Process with появился **Third-party model…**. Для совместимой локальной
модели можно ввести ID или выбрать её папку через **Choose folder…**: визуальная
